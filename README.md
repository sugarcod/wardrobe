# Гардероб — цифровой гардероб с манекеном

Веб-приложение для личного гардероба: загружайте фото своих вещей **без фона** (PNG/WebP с прозрачностью), сортируйте их, отмечайте тегами и собирайте образы, надевая вещи слоями на нейтральный манекен.

Без маркетплейса и социальной ленты. Работает без аккаунта (данные в браузере, IndexedDB); по желанию — вход через Google и синхронизация между устройствами через Firebase.

## Возможности

- **Гардероб.** Сетка вещей на клетчатом фоне прозрачности. Фильтры по категории, цвету, сезону и поводу, сортировка (новые, категория, цвет), поиск по тегам и названию.
- **Загрузка.** Перетаскивание или выбор файлов, можно сразу несколько. PNG/WebP (JPEG тоже принимается, но с предупреждением). Лимит 8 МБ на файл. Фото уменьшаются до 1200 px, прозрачные поля обрезаются, картинка сжимается в WebP.
  - Если фон не убран (почти нет прозрачных пикселей), приложение предупредит и предложит **грубо удалить светлый фон** (заливка от краёв + ползунок чувствительности).
  - **Автоподсказки** — только черновик: категория, сезон, повод и цвет по имени файла (русские и английские слова: «джинсы», «jeans», «платье», «dress»…) и цвет по доминирующему цвету картинки. Вы всё подтверждаете перед сохранением.
- **Карточка вещи.** Превью, категория, цвет, сезон, повод, свои теги, замена фото, удаление с подтверждением.
- **Сбор образа.** Манекен в центре (SVG-силуэт без лица и бренда), гардероб слева, слои и теги образа справа.
  - Клик по вещи надевает её в свою зону (голова, торс, ноги, стопы, рука, шея); повторный клик снимает.
  - В зоне одна вещь (украшения и «другое» можно сочетать). Платье снимает верх и низ, а верх или низ снимают платье.
  - Порядок слоёв снизу вверх: низ → верх → платье → верхняя одежда → обувь → сумка → головной убор → украшения.
  - Вещь можно двигать мышью или пальцем (и стрелками), масштабировать и отражать. Есть «Снять всё» и крестик на каждом слое.
  - Светлый и тёмный фон сцены.
- **Образы.** Сохранение с названием и датой, галерея с миниатюрами, открытие для редактирования («Обновить» или «Как новый»), удаление с подтверждением.
- **Что надеть?** Подбор образа из ваших вещей: выберите сезон (текущий определяется по дате) и повод. Приложение соберёт платье или верх с низом, обувь, верхнюю одежду в холодный сезон, иногда сумку, головной убор или украшение. Нейтральные цвета сочетаются со всем, ярких не больше двух. Можно нажать «Ещё вариант» или «Надеть на манекен».
- **Настройки.** Сколько места занято и сколько доступно (`navigator.storage.estimate()`), статус постоянного хранения, резервная копия в JSON (экспорт, импорт «добавить» или «заменить всё»), удаление всех данных.
- **Адаптивность.** На телефоне манекен сверху, ниже гардероб с горизонтальной прокруткой по категориям, навигация внизу экрана.

## Как сделать фото без фона

Подойдёт любой инструмент удаления фона: встроенный в iPhone (долгое нажатие на объект в «Фото» → «Скопировать» или «Поделиться»), Android, remove.bg, Canva и т. п. Сохраняйте результат как PNG.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
npm run preview  # просмотр сборки
```

Требуется Node.js 20+.

## Деплой на Netlify

В репозитории уже есть `netlify.toml`:

- команда сборки: `npm run build`
- папка публикации: `dist`
- SPA-редирект `/*` → `/index.html` (200)

Подключите репозиторий в Netlify (Add new site → Import from Git) — настройки подтянутся автоматически.

## Вход через Google и синхронизация (Firebase)

Необязательная функция: если Firebase не настроен, кнопка входа скрыта и приложение работает только локально. Используются только **Firebase Auth** и **Cloud Firestore**; Firebase Storage не нужен (бесплатный план Spark подходит).

### Настройка

1. Создайте проект в [Firebase Console](https://console.firebase.google.com/), добавьте **Web app**.
2. **Authentication → Sign-in method → Google** — включить. В **Authentication → Settings → Authorized domains** добавьте домен сайта (например, `ваш-сайт.netlify.app`).
3. **Firestore Database → Create database** (production mode), затем опубликуйте правила из `firestore.rules`: вставьте их в консоли (Firestore → Rules) или выполните `npx firebase-tools deploy --only firestore:rules --project <project-id>`.
4. Укажите конфиг веб-приложения одним из способов:
   - впишите объект в `src/firebaseConfig.ts` → `MANUAL_CONFIG` (веб-конфиг Firebase публичный, его можно коммитить);
   - или задайте переменные окружения (см. `.env.example`) в `.env.local` или в Netlify → Environment variables: `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID` (необязательно: `VITE_FIREBASE_STORAGE_BUCKET`, `VITE_FIREBASE_MESSAGING_SENDER_ID`). Переменные окружения важнее `MANUAL_CONFIG`.

### Как устроено

- Вход: `signInWithPopup` с Google; если окно заблокировано или это мобильное устройство без поддержки окон — `signInWithRedirect`.
- Данные в Firestore:
  - `users/{uid}/items/{id}` — вещь (как локально, без картинки) + `updatedAt`, `deleted`, `imageRev`;
  - `users/{uid}/images/{id}` — фото: `{ dataUrl, rev, updatedAt }`, base64 WebP, не больше ~700 КБ (при необходимости ужимается);
  - `users/{uid}/outfits/{id}` — образ + `updatedAt`, `deleted`.
- IndexedDB остаётся локальным хранилищем и офлайн-кэшем; у Firestore включён `persistentLocalCache`, поэтому изменения без интернета отправятся позже.
- **Первый вход:** локальные вещи и образы объединяются с облаком — чего нет в облаке, отправляется, чего нет на устройстве, скачивается. Дальше — синхронизация в реальном времени (`onSnapshot`).
- Конфликты — **last-write-wins** по `updatedAt`. Удаления хранятся как «надгробия» (`deleted: true`), чтобы дойти до всех устройств.
- Статус в шапке: «Синхронизировано», «Синхронизация…», «Офлайн».
- **Выход:** можно оставить данные на устройстве или удалить их с устройства (в облаке они остаются).
- Если на устройстве лежат данные другого аккаунта, при входе приложение спросит: объединить или заменить данными из облака.
- «Удалить все данные» в настройках при входе в аккаунт удаляет данные и в облаке.

## Хранение данных

Вещи и образы хранятся в **IndexedDB** (база `wardrobe`, библиотека [`idb`](https://github.com/jakearchibald/idb)). Места хватает на сотни вещей: браузер обычно выделяет сайту гигабайты.

| Хранилище | Содержимое |
| --- | --- |
| IndexedDB `items` | метаданные вещи: `{ id, name, category, tags[], color, season, occasion?, createdAt, updatedAt?, imageRev? }` |
| IndexedDB `images` | картинка вещи как `Blob` (WebP/PNG), ключ — `id` вещи |
| IndexedDB `tombstones` | отметки об удалении для синхронизации |
| IndexedDB `outfits` | `{ id, name, createdAt, updatedAt?, layers: [{ itemId, x, y, scale, flip }] }` |
| localStorage `wardrobe.draft.v1` | текущий образ на манекене |
| localStorage `wardrobe.prefs.v1` | настройки (тёмная сцена) |

В приложении вещь имеет прежнюю форму `{ …, imageDataUrl }`: при загрузке Blob превращается в object URL (`blob:`). В резервной копии JSON картинки сохраняются как data URL, так что файл самодостаточен; при импорте они снова превращаются в Blob.

- При запуске вызывается `navigator.storage.persist()`, чтобы браузер не удалял данные при нехватке места.
- **Миграция:** если остались данные старой версии в localStorage (`wardrobe.items.v1`, `wardrobe.outfits.v1`), при первом запуске они автоматически переносятся в IndexedDB, после чего старые ключи удаляются (только после успешной записи).
- Если место на устройстве закончится (`QuotaExceededError`), приложение покажет сообщение и ничего не потеряет.

Категории (`category`): `top` — верх, `bottom` — низ, `dress` — платье/комбинезон, `outerwear` — верхняя одежда, `shoes` — обувь, `bag` — сумка, `hat` — головной убор, `jewelry` — украшение, `other` — другое.
Сезон: `spring`, `summer`, `autumn`, `winter`, `all`. Повод: `daily`, `work`, `evening`, `sport`.
`x`, `y` — смещение от стандартной зоны в долях размера сцены; `scale` — масштаб; `flip` — отражение по горизонтали.

## Структура

```
src/
  App.tsx              — оболочка, навигация, загрузка файлов (drag-and-drop)
  store.tsx            — состояние, загрузка из IndexedDB, миграция
  ui.tsx               — уведомления и диалоги подтверждения
  constants.ts         — категории, зоны манекена, сезоны, поводы
  lib/
    image.ts           — уменьшение, обрезка, проверка прозрачности, удаление фона, доминирующий цвет
    process.ts         — обработка загруженного файла
    suggest.ts         — подсказки по имени файла
    colors.ts          — палитра цветов, нейтральные цвета
    outfit.ts          — правила надевания слоёв и подбор «Что надеть?»
    hit.ts             — попадание по непрозрачным пикселям при перетаскивании
    db.ts              — IndexedDB (idb): вещи, картинки-Blob, образы; persist/estimate
    storage.ts         — черновик и настройки (localStorage), миграция, экспорт/импорт
    cloud.ts           — Firebase Auth + Firestore, движок синхронизации (грузится лениво)
    syncMerge.ts       — чистая логика слияния last-write-wins (+ syncMerge.test.ts)
  cloud.tsx            — вход/выход, статус синхронизации
  firebaseConfig.ts    — конфиг Firebase (MANUAL_CONFIG или VITE_FIREBASE_*)
  components/          — Stage (сцена), Mannequin (SVG), ItemCard, ItemForm, UploadDialog, ItemDetail, Filters…
  screens/             — Гардероб, Сбор образа, Что надеть?, Образы, Настройки
```
